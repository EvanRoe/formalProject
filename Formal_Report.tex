\begin{verbatim}

\end{verbatim}
turned into this:
\begin{verbatim}
 var isS := checkSet(s);
  if !isS {
    return false;
  }
  for x := 0 to |s|
  {
    var y: int := s[x];             

    if y % 2 != 0{
      assert !isEven(y);
      return false;
    }
    ModuloEven(y);
  }
  return true;
\end{verbatim}
Reasoning: The first change is to put a set guard, so that the set part of Even set is verified. In this case, some of the body could be rewritten more simply as it was written by a different member. The next change to help verify comes when y is not even, and a predicate is used to tell Dafny that there is a non-even value in the sequence. If all the values pass that clause, then ModuloEven() confirms that it is even, and since we know that it is a set from the first guard, the output must be true.

setScale:
\begin{verbatim}
  t := [];
  var y: int := 0;

  for i := 0 to |s|
    {
      assert (s[i] * n) !in t;
      y := s[i] * n;
      t := t + [y];
    }
  forall k | k in t
    ensures exists v :: v in s && k == v * n
  {
    var j :| 0 <= j < |s| && k == s[j] * n;
    assert s[j] in s;
  }
\end{verbatim}
Turned into this:
\begin{verbatim}
 t := [];

  for i := 0 to |s|
  {
    var y := s[i] * n;

    if isEvenSet(s) {
      EvenTimes(s[i], n);
    } else if isEven(n) {
      EvenTimes(s[i], n);
    }

    if isOddSet(s) && isOdd(n) {
      OddTimesOdd(s[i], n);
    }

    if scaled !in t {
      t := t + [y];
    }
  } 
\end{verbatim}
Reasoning: After copying the code into the part 3 block, we soon realised that the forall and assert lines at the end did not help Dafny verify any of the new pre- and postconditions, so those could be quickly removed. Dafny highlighted the last two postconditions as the problems, and with some trial and error, the two if blocks in the middle finally helped prove those postconditions. The two blocks use the left hand side of the postconditions as guards, and then help to confirm that the new value y is the right parity before going into t.


setProduct:
\begin{verbatim}
  t := [];
  var i := 0;
  while i < |s1|
  {
    var j := 0;
    while j < |s2|
    {  
      var prod := s1[i] * s2[j];
      
      if prod !in t {
        t := t + [prod];
      }
    }
\end{verbatim}
turned into this:
\begin{verbatim}
  t := [];
  var i := 0;

  while i < |s1|
  {
    var j := 0;
    while j < |s2|
    {
      var prod := s1[i] * s2[j];
      if prod !in t {
        if isEvenSet(s1) || isEvenSet(s2) {
          EvenTimes(s1[i], s2[j]);
        }
        if isOddSet(s1) && isOddSet(s2) {
          OddTimesOdd(s1[i], s2[j]);
        }
        t := t + [prod];
      }
      j := j + 1;
    }
    i := i + 1;
  }
\end{verbatim}
Reasoning: Here the purpose of the changes were to satisfy the last two postconditions, where for s1 being an even set then t had to be and if both input sets were odd sets then t would have to be too. Those if statements take the postconditions as guards, and if they're true then it confirms that the product is even for the first one, confirming that prod must be even, and odd for the second one, confirming that prod must be odd. This helps dafny verify the parity of the to be added value.

\section{Reflection}

- Which methods were hardest and why
- How proof attempts changed your understanding of specification and correctness
- Whether AI helped or slowed you down
- Any other thoughts on the verification experience

For Part 3 the method that gave the most problems was the setProduct method. The nested loop and the 5 postconditions meant that Dafny needed to search through many loop iterations to verify the method. Many times we were faced with a verification timeout which meant we were not even informed about what part of the method could not be verified. The nested loop also meant that each loop needed its set of invariants, which did not come intuitively to duplicate the invariants over both loops.
AI definitely helped in this case, because since it was a new programming language essentially, learning its intricacies quickly was made simple with the use of AI. If we were stumped on a method in part 2 or 3, we could turn to AI to learn how Dafny evaluated and verified different postconditions types. Otherwise I expect we would have needed to dig through Dafny documentation to get there.
